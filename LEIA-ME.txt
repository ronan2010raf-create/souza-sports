CONFIGURAÇÃO INICIAL SUPABASE
1. Execute supabase-setup.sql no Supabase SQL Editor se ainda não tiver feito.
2. Configure no index.html o Project URL e a Publishable key (sb_publishable_) do Supabase.
3. Nunca publique Secret key/service_role, senha de banco de dados ou senha de usuários.

ESTOQUE COMPARTILHADO E CONVITES
1. Abra supabase-shared-workspace.sql no GitHub.
2. Copie todo o conteúdo e execute no Supabase > SQL Editor > New query > Run.
   Esse segundo script cria o espaço compartilhado, convites de uso único e validações
   de permissões no servidor. É necessário para a nova versão.
3. Abra o SOUZA SPORTS no telefone do administrador e entre com a conta principal.
4. Na tela de vinculação, clique em “Criar estoque compartilhado com meus dados atuais”.
   O procedimento migra a linha antiga dessa conta para o novo espaço compartilhado.
5. Depois de carregar, abra a aba “Acessos” e gere um convite para colaborador.
6. Envie o código de uso único ao colaborador. Ele cria uma conta própria no aplicativo
   e cola o convite na tela de vinculação. O código expira em 7 dias e só pode ser usado uma vez.
7. Outros aparelhos devem entrar usando suas próprias contas, já vinculadas ao mesmo espaço.

PERMISSÕES
Administrador: gerencia cadastros, preços, encomendas, estoque e acessos.
Colaborador: consulta o estoque e registra vendas e entradas. Não recebe os custos
internos nem as encomendas na tela. O servidor bloqueia alterações a cadastros de
produtos, custos, encomendas e histórico anterior de movimentações.

SEGURANÇA E BACKUPS
A tabela do espaço compartilhado usa Row Level Security.
A chave Publishable pode ficar no frontend quando RLS está configurado corretamente.
Nunca coloque Secret key ou service_role no GitHub, no index.html ou em mensagens.
Faça backups JSON regularmente e armazene cópias fora do aparelho.
O plano gratuito não oferece backups automáticos e projetos com baixa atividade
podem ser pausados. Confira os limites atuais no painel do Supabase.


PERFIL DE SÓCIO
Para adicionar sócio com os mesmos acessos operacionais, execute também
supabase-partner-role.sql no Supabase > SQL Editor > New query.
Depois, atualize o SOUZA SPORTS e entre com a conta de administrador.
Na aba Acessos, gere o convite de sócio. O sócio cria conta própria e aceita
o código de uso único. Somente o administrador principal pode gerar convites;
o sócio tem os acessos operacionais completos (produtos, preços, compras,
vendas, encomendas e relatórios).


GRADES DE TAMANHOS
No cadastro de produtos, os tipos FEMINA usam P, M, G, GG, XG, 2XL, 3XL e 4XL.
Os produtos do tipo INFANTIL usam 16, 18, 20, 22, 24, 26 e 28.
Vendas, compras, entradas, estoque e encomendas aceitam as duas grades.
Para ativar o acesso de sócio e a validação dos tamanhos infantis no banco,
execute a versão atual de supabase-partner-role.sql no Supabase SQL Editor.


CRIAR USUÁRIOS SEM CONFIRMAÇÃO DE E-MAIL
- O administrador principal pode criar contas na aba Acessos.
- O login é o endereço de e-mail informado; a senha é definida pelo administrador.
- A Edge Function create-workspace-user cria a conta com e-mail confirmado e associa imediatamente ao estoque compartilhado.
- A operação administrativa é executada no servidor Supabase. Nunca copie uma chave secreta/service_role para o index.html.
- Publicar a função em Supabase > Edge Functions > Deploy a new function > Via Editor, usando o código em supabase/functions/create-workspace-user/index.ts.
- A função usa as variáveis seguras padrão do projeto Supabase (SUPABASE_URL, SUPABASE_PUBLISHABLE_KEYS e SUPABASE_SECRET_KEYS).
- Somente membros com perfil owner podem criar usuários. Escolha Sócio (partner) ou Colaborador (collaborator).
- O perfil Sócio exige que o script supabase-partner-role.sql esteja aplicado no banco.


COMPRAS E IMPORTAÇÕES
- A aba Compras e importações registra pedidos com vários produtos e tamanhos, fornecedor, referência, datas, rastreamento, etapa e custos adicionais.
- Os valores de frete, importação, impostos, alfândega e demais despesas são divididos igualmente pelo total de peças do pedido.
- O estoque só recebe as mercadorias quando o status é alterado para Recebido. O recebimento é processado uma única vez.
- A compra direta para cliente cria movimentações de venda direta e não aumenta o estoque disponível.
- As compras são sincronizadas pelo mesmo estoque compartilhado e incluídas no backup JSON.
- Execute a versão atualizada de supabase-partner-role.sql no SQL Editor para preservar os pedidos de compra quando um colaborador registrar vendas ou entradas.
